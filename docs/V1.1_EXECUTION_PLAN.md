## 1. 纪律与门禁（规格 §19 的可执行化）

1. **阶段顺序不可调换**：Rust（A–D）→ 前端拆分（E）→ 前端功能（F）→ 收尾（G）。前端功能开发开始前，schema v3 与领域测试必须全绿。
2. **TDD**：每个任务先写失败测试（Rust `cargo test` / 前端 `vitest`），再实现转绿；禁止先实现后补测试。
3. **30 秒资格规则只存在于 Rust**（`repository.rs`），React 仅渲染 `statistics_eligible` / `qualification_reason` 字段。
4. **标签一律走 `tags` 表 + `tag_id` 外键**，禁止字符串标签。
5. 不改数据目录、应用标识、WAL、integrity check、损坏文件自愈、revision 乐观并发、session 幂等。
6. 不接入 RDS/登录/网络；不加 `sync_status`/`remote_id`/`outbox` 等字段。
7. **不整体重写 `App.tsx`**：只按 §5.2 拆出本轮涉及的模块（阶段 E）。
8. **每阶段门禁**（全绿才进入下一阶段）：
   - `cd src-tauri && cargo test`
   - `npx tsc --noEmit`
   - `npx vitest run`
   - `pnpm tauri build --no-bundle`（阶段 G 起含完整 NSIS 打包）
9. **每任务上报**：commit SHA + 变更文件清单 + 新增/通过测试数。遇计划外问题（迁移失败、回归、脏树）立即 halt-and-report。
10. push 门控：每阶段结束推送 feature 分支需一次确认；合入 `main` 与打 tag 另行门控。

## 5. 风险控制（对应规格 §18）

| 风险 | 计划内控制 |
|------|-----------|
| 迁移破坏真实数据 | 开工前备份真实库副本；A 阶段用副本做升级演练；迁移单事务 + `foreign_key_check`；保留损坏自愈兜底 |
| 结束与自然完成竞争 | C1 统一 finalize + session ID 幂等 + `newly*` 标志；C5 专项竞争测试 |
| 统计口径回退 | C7 后全仓 grep 禁止 `logs.length` 参与统计；F6 测试锁定 |
| App.tsx 回归面扩大 | E 阶段"只移动不改逻辑"，diff 审查 + 存量 17 测试零回退 |
| 隐藏记录泄漏 | Repository 层过滤（C6），前端不持有 all 数据 |
| 模式切换语义变更引发使用困惑 | D-2 确认 + README/CHANGELOG 明示行为变化 |

**回滚策略**：feature 分支上每任务可独立 revert；迁移一旦发布（v1.1.0 安装包）不可回退 schema——发布前必须完成 G4 实机回归。
