## 1. 纪律与门禁（规格 §19 + 评审补充）

1. 阶段顺序不可调换：Rust（A–D）→ 纯机械拆分（E）→ 前端功能（F）→ 收尾（G）。
2. TDD：每个任务先写失败测试再实现。
3. 30 秒资格规则只存在于 Rust；React 仅渲染 `statistics_eligible` / `qualification_reason`。
4. 标签一律 `tags` 表 + `tag_id` 外键；禁止字符串标签。
5. 不改数据目录、应用标识、WAL、integrity check、revision 并发、session 幂等；**不弱化损坏自愈**。
6. 不接入 RDS/登录/网络；不加同步类字段。
7. 不整体重写 `App.tsx`；**阶段 E 限定为纯机械拆分**——`ConfirmDialog`、`TagManager` 等新组件一律放入阶段 F，不混入"零行为变化"提交（评审建议 9）。
8. 每阶段门禁：`cargo test` + `tsc --noEmit` + `vitest run` + `pnpm tauri build --no-bundle`（G 含完整 NSIS）。
9. 每任务上报 commit SHA + 变更文件 + 测试数；异常 halt-and-report。
10. push 门控：每阶段推送 feature 分支需一次确认；合入 `main`、打 tag、发 Release 另行门控。
11. **最终 EXE 必须在 Windows x64 环境构建**，并执行覆盖安装 / 全新安装 / 卸载保留数据 / 旧数据库升级 / SHA-256 校验（评审建议 10，并入 G4）。

## 5. 风险与回滚（规格 §18 + 评审 #1/#2 落地）

| 风险 | 计划内控制 |
|------|-----------|
| 迁移破坏真实数据 | **迁移失败 ≠ 损坏**：A0 分流（迁移失败回滚保留原库并阻止启动）；A0b 升级前时间戳副本；A4 真实副本演练；单事务 + foreign_key_check |
| 重建表顺序错误（FK 引用） | A2 固定顺序：先删 sessions 再删 tasks、先改 tasks 名再改 sessions 名；禁止事务内关 foreign_keys |
| 结束与自然完成竞争 | C2 幂等先于 revision 校验 + 两组方向性并发测试 |
