# 已知问题清单（Known Issues）

发布日期：2026-09-05（v1.1.0）　|　状态标注：影响 / 规避 / 计划

## 功能类

### KI-08　计时未到期时「完成」接口被拒绝（设计内保护）
- **现象**：`complete_timer` 仅允许在倒计时归零（±250ms 调度容差）时成功；提前调用返回 CONFLICT，不写任何数据。
- **影响**：无——提前结束请用「结束」按钮（走 finish_timer，满 30 秒计入统计）。

### KI-09　重置产生的记录为内部记录（v1.1 裁定）
- **现象**：重置写入 abandoned/finish_reason=reset 记录，任何页面都不显示，仅完整 JSON/CSV 导出可见。
- **影响**：无——活动栏只显示计入统计的专注记录。

### KI-10　计时进行中切换模式被禁用（行为变更）
- **现象**：running/paused 时模式按钮禁用（tooltip：请先结束或重置当前计时）。
- **影响**：取代 v1.0.0 的「切换即提交」；先「结束」再切换即可。

### KI-01　全局快捷键冲突时热键不可用（设计内降级）
- **现象**：`Ctrl+Alt+Space` 被其它程序注册时，本应用启动后该热键无效，顶部显示警告横幅。
- **影响**：低——托盘菜单与主窗口按钮不受影响。
- **规避**：关闭占用该热键的程序后重启本应用。
- **计划**：未来版本提供自定义快捷键设置项。

### KI-02　托盘退出后恢复的暂停会话需手动继续（设计行为）
- **现象**：计时中通过托盘「彻底退出」，下次启动会话处于暂停态，需点击「继续」。
- **影响**：无——这是有意设计，防止专注时间被悄悄消耗。

### KI-03　数据库损坏后自动重建（设计内自愈）
- **现象**：极端情况（磁盘故障/进程写入中被强杀）下 SQLite 文件损坏时，应用启动会将其重命名为 `abyssal-reverie.sqlite.corrupt-<时间戳>` 并以全新库启动，历史数据不在新库中。
- **影响**：低概率；损坏文件完整保留，可用 `sqlite3 .recover` 尝试人工抢救。
- **规避**：重要数据可定期「设置 → 导出备份」。

### KI-04　卸载不删除用户数据（设计行为）
- **现象**：卸载后 `%APPDATA%\com.abyssalreverie.focus\` 保留（含全部任务/会话/设置；目录名为 bundle identifier）。
- **规避**：需彻底清除时手动删除该目录。

## 环境类

### KI-05　安装包体积约 273 MB
- **原因**：内嵌 WebView2 offlineInstaller（约 200+ MB）以支持无网安装；应用本体仅约 20 MB（媒体已内嵌）。
- **计划**：未来可提供 online-installer 变体（需联网但体积小）。

### KI-06　移动版 / macOS / Linux 未支持
- 当前版本仅面向 Windows 10/11 x64；Tauri 代码结构已为跨平台预留，但未做适配验证。

### KI-07　数据库来自更高版本时行为未定义
- 若用旧版程序打开新版创建的数据库（`user_version` 更高），迁移逻辑视为已迁移、直接运行。
- **影响**：极低（当前仅存在 v2 一个 schema）；未来版本将加入版本守卫。

## 待实机确认（开发环境无法覆盖）

以下项已通过代码审计与自动化测试，但最终结论需在真实 Windows 环境确认（详见 `REGRESSION_REPORT.md` Round 6 验收矩阵）：

- Win10 / Win11、1366×768–2K、单/双显示器下的布局与 DPI 缩放（100–200%）。
- 中文 / 空格 / 非系统盘安装路径的完整功能（资源内嵌 exe，理论无路径依赖）。
- 启动耗时的绝对值（目标 ~3 s，开发机 release 构建加载正常）。
- 连续运行 24 h+ 的内存稳定性。
- 实际安装器的升级（覆盖安装）与卸载流程。
